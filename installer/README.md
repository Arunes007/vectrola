# Vectrola Installer

Developer documentation for the Vectrola installer scripts.

## Overview

The installer provides a single-command installation experience for Vectrola across all platforms:

- **Unix (macOS/Linux)**: `install.sh` - Bash script
- **Windows**: `install.ps1` - PowerShell script

Both scripts provide:
- Interactive configuration prompts
- Prerequisite checking (Git, Python 3.10+)
- Python virtual environment setup
- Dependency installation
- Shell/PATH configuration
- Optional local Qdrant setup via Docker

## Usage

### Interactive Installation (Recommended)

**macOS/Linux:**
```bash
curl -fsSL https://raw.githubusercontent.com/Arunes007/vectrola/main/installer/install.sh | bash
```

**Windows (PowerShell):**
```powershell
irm https://raw.githubusercontent.com/Arunes007/vectrola/main/installer/install.ps1 | iex
```

### Non-Interactive Installation

For CI/CD or scripted installations:

**macOS/Linux:**
```bash
# With defaults (local Ollama + hosted Qdrant)
curl -fsSL .../install.sh | bash -s -- --non-interactive

# With local everything
curl -fsSL .../install.sh | bash -s -- --non-interactive --llm=local --qdrant=local

# With custom remote Qdrant
curl -fsSL .../install.sh | bash -s -- --non-interactive --qdrant-url=https://my-qdrant.example.com
```

**Windows:**
```powershell
# With defaults
& ([scriptblock]::Create((irm .../install.ps1))) -NonInteractive

# With local Qdrant
& ([scriptblock]::Create((irm .../install.ps1))) -NonInteractive -Qdrant local
```

## Command-Line Options

### Unix (install.sh)

| Option | Description |
|--------|-------------|
| `-h, --help` | Show help message |
| `--non-interactive` | Skip prompts, use defaults or specified options |
| `--llm=TYPE` | LLM type: `local` (default), `remote` |
| `--llm-url=URL` | Custom LLM URL (implies `--llm=remote`) |
| `--qdrant=TYPE` | Qdrant type: `hosted` (default), `local`, `remote` |
| `--qdrant-url=URL` | Custom Qdrant URL (implies `--qdrant=remote`) |
| `--qdrant-api-key=KEY` | Qdrant API key for authenticated remotes |

### Windows (install.ps1)

| Parameter | Description |
|-----------|-------------|
| `-Help` | Show help message |
| `-NonInteractive` | Skip prompts, use defaults or specified options |
| `-Llm TYPE` | LLM type: `local` (default), `remote` |
| `-LlmUrl URL` | Custom LLM URL |
| `-Qdrant TYPE` | Qdrant type: `hosted` (default), `local`, `remote` |
| `-QdrantUrl URL` | Custom Qdrant URL |
| `-QdrantApiKey KEY` | Qdrant API key |

## Environment Variables

Both installers respect these environment variables:

| Variable | Default | Description |
|----------|---------|-------------|
| `VECTROLA_VERSION` | `main` | Git branch/tag to install |
| `VECTROLA_INSTALL_DIR` | `~/.vectrola` | Installation directory |
| `VECTROLA_CONFIG_DIR` | `~/.config/vectrola` | Configuration directory |

## What Gets Installed

```
~/.vectrola/                  # Installation directory
├── .venv/                    # Python virtual environment
│   └── bin/                  # Executables (vectrola, python, pip)
├── vectrola/                 # Source code
├── pyproject.toml
└── ...

~/.config/vectrola/           # Configuration directory
├── .env                      # Generated configuration
├── library.json              # User library (created on first use)
└── qdrant/                   # Local Qdrant data (if using local Qdrant)
```

## Configuration Options

### LLM Options

| Option | URL | Notes |
|--------|-----|-------|
| Local Ollama | `http://localhost:11434` | Private, no API costs. Requires Ollama. |
| Remote | User-provided | Bring your own Ollama-compatible endpoint |

### Qdrant Options

| Option | URL | Notes |
|--------|-----|-------|
| Hosted | `https://qdrant.vectrola.dev` | Easy start, no Docker needed |
| Local | `http://localhost:6333` | Full control, requires Docker |
| Remote | User-provided | Bring your own Qdrant instance |

## Generated Configuration

The installer creates `~/.config/vectrola/.env`:

```bash
# Generated by Vectrola installer
OLLAMA_HOST=http://localhost:11434
QDRANT_URL=https://qdrant.vectrola.dev
# QDRANT_API_KEY=xxx  # If using authenticated remote
```

This file is read by Vectrola on startup.

## Testing the Installer

### Local Testing (Unix)

```bash
# Test help
bash installer/install.sh --help

# Test syntax
bash -n installer/install.sh

# Run shellcheck
shellcheck installer/install.sh

# Dry run (in a clean environment)
docker run -it --rm -v $(pwd):/vectrola ubuntu:22.04 bash -c "
  apt update && apt install -y curl git python3.11 python3.11-venv
  cd /vectrola
  bash installer/install.sh --non-interactive
"
```

### Local Testing (Windows)

```powershell
# Test syntax
$null = [System.Management.Automation.PSParser]::Tokenize((Get-Content installer/install.ps1 -Raw), [ref]$null)

# Test help
.\installer\install.ps1 -Help
```

## Troubleshooting

### Python venv fails on Linux

If you see "Failed to create virtual environment", install the venv module:

```bash
# Debian/Ubuntu
sudo apt install python3-venv

# Or for specific version
sudo apt install python3.11-venv
```

### Ollama not detected

The installer checks if Ollama is running by connecting to `http://localhost:11434`. If Ollama is installed but not running:

```bash
ollama serve
```

### Docker permission denied

On Linux, you may need to add your user to the docker group:

```bash
sudo usermod -aG docker $USER
# Log out and back in
```

### PATH not updated

If `vectrola` command is not found after installation:

1. Open a new terminal (required for PATH changes)
2. Or manually source your shell config:
   ```bash
   source ~/.zshrc  # or ~/.bashrc
   ```
